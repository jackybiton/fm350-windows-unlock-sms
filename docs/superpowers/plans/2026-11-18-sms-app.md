# FM350 SMS Desktop App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the v0.1.0 background SMS receiver (`src/Fm350Sms`) into a Hebrew WPF desktop app that stores every SMS in SQLite, shows conversations grouped by Google contact, saves numbers as contacts, deletes messages locally, and sends SMS over MBIM.

**Architecture:** One per-user process (`Fm350Sms.exe`, WinExe) hosts a WPF window, a tray icon and a background modem loop. Pure logic (PDU encode/decode, phone normalization, contact parsing, thread grouping) lives in `Core/` with no WPF dependency and is tested by `Fm350Sms.exe --self-test`. `Data/SmsDatabase` owns all SQLite access. `Modem/` wraps `IMbnSms`. `Ui/` is WPF code-behind.

**Tech Stack:** .NET 10, WPF + WinForms `NotifyIcon`, `Microsoft.Data.Sqlite` (10.0.x, same release train as `Microsoft.Extensions.Hosting` 10.0.12 used by the service project), Windows Mobile Broadband COM API (`mbnapi.h`), WinRT toasts.

**Spec:** `docs/superpowers/specs/2026-11-18-sms-app-design.md`

## Global Constraints

- Target `net10.0-windows10.0.26100.0`, `SupportedOSPlatformVersion` 10.0.19041.0, x64, `Nullable` enable, `TreatWarningsAsErrors` true.
- Same exe name `Fm350Sms.exe`, data folder `%LOCALAPPDATA%\FM350Sms`, HKCU Run value `FM350 SMS`, AppUserModelId `FM350.Sms`.
- Database file `%LOCALAPPDATA%\FM350Sms\sms.db`.
- No administrator rights; no network access; no Google credentials stored.
- Never send an SMS except on the user's Send click. Never delete from the modem unless `--delete-after-save` / the settings checkbox is on.
- UI text is Hebrew, window `FlowDirection="RightToLeft"`.
- National numbers: leading `0` → `+972`; `00` → `+`. Last-9-digits fallback only when both sides have ≥ 9 digits. Short codes and alphanumeric senders: exact match only.
- `contacts/` (user's Google export) is gitignored and must never be committed.
- All tests run through `Fm350Sms.exe --self-test` (exit 0 = pass); CI already invokes it.
- Work on branch `feature/sms-app`; never commit `Set-FM350Mode.ps1`, `Set-FM350Network.ps1`, `.txt` (user's own untracked files).

## Review Focus

- A number saved under two contacts (or twice in the CSV) → the first contact in file order wins, deterministically. Test in Task 4.
- An alphanumeric sender like `Partner` must never match a contact through the last-9 fallback. Test in Task 2.
- A deleted message whose PDU is still on the modem must not reappear on the next poll. Test in Task 3.
- App killed while a message is `sending` → on next start it shows `failed` with a retry, not stuck. Test in Task 3.
- Importing `messages.txt` (or re-running the migration) twice must not duplicate messages. Test in Task 3.

### Task 5: SMS-SUBMIT encoder

**Files:** Create `src/Fm350Sms/Core/SmsSubmit.cs`, `SmsSubmitTests.cs`

**Interfaces:**
- Produces:
  - `record SubmitPdu(string Hex, byte TpduLength)` — `Hex` includes a leading `00` (use SIM SMSC); `TpduLength` = byte count excluding that octet (the `size` argument of `SmsSendPdu`).
  - `static class SmsSubmit`
    - `bool FitsGsm7(string text)` — every char in the GSM basic or extension table.
    - `(int Parts, int CharsLeft) Measure(string text)` — GSM: 160 single / 153 per part (extension chars count 2); UCS2: 70 single / 67 per part (UTF-16 code units).
    - `IReadOnlyList<SubmitPdu> Encode(string destination, string text, byte reference)` — first octet `0x11` (or `0x51` with UDH), MR `00`, destination from `PhoneNumbers.Key` (international TOA `91` when `+`, else `81`), PID `00`, DCS `00`/`08`, VP relative `AA`; multi-part uses 8-bit concat IE `00 03 ref total seq`, GSM payload padded with 1 fill bit after the 6-octet UDH.
  - Move the GSM 7-bit tables out of `SmsPdu` into `Core/Gsm7.cs` (`static class Gsm7 { bool TryEncode(char c, out int septet, out bool extended); string Unpack(...); byte[] Pack(IReadOnlyList<int> septets, int fillBits); }`) used by both.

- [ ] **Step 1: Write failing tests:**
  - `Encode("+46708251358", "hellohello", 0)` → single PDU `Hex == "0011000B916407281553F80000AA0AE8329BFD4697D9EC37"`, `TpduLength == 23`.
  - `Measure(new string('a',160)) == (1, 0)`, `Measure(new string('a',161)).Parts == 2`, `Measure(new string('א',70)) == (1, 0)`, `Measure(new string('א',71)).Parts == 2`, `Measure("€").CharsLeft == 158`.
  - Hebrew `Encode("0505550123", "שלום", 0)`: DCS `08`, destination TOA `91` with `+972505550123`, UD `05E905DC05D505DD`.
  - Decode-back check: for a 200-char Hebrew text, every part's UD after the UDH, concatenated and read as UTF-16BE, equals the input, and part headers read `ref, 3, 1..3`.
- [ ] **Step 2:** Run `--self-test`; expected FAIL.
- [ ] **Step 3:** Implement.
- [ ] **Step 4:** Run `--self-test`; expected all PASS, including the old PDU decode cases.
